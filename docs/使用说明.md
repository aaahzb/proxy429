# Proxy429 使用说明

本地 Anthropic 兼容 HTTP 代理：吃掉上游 429 / 5xx，自动指数退避重试，让 Claude Code 无感。
**跨平台一致**：macOS / Windows / Linux 行为完全相同——启动后纯托盘运行（无终端窗口），状态、日志、配置都在一个本地网页控制台里看和改。

---

## macOS 上运行哪个文件？

**双击 `Proxy429.app`** 就行。它是个菜单栏应用（无 Dock 图标、无终端窗口），关掉 Finder 也不影响。

- **首次启动被 Gatekeeper 拦**：在 Finder 里**右键 -> 打开**一次即可（ad-hoc 签名，非开发者证书）。
- 启动后菜单栏出现状态灯：🟡灰(空闲) / 🟡黄(已发待回) / 🟢绿(流式中)。
- 点菜单栏图标 -> **「查看日志」**，默认浏览器打开网页控制台 `http://127.0.0.1:8080/__logs`。
- **退出**：菜单栏图标 -> **「退出代理」**。关掉浏览器标签页**不会**退出代理（只是隐藏控制台）。

> Windows 双击 `proxy429.exe`（不弹控制台窗口），系统托盘图标右键 -> 「查看日志」。Linux 运行 `./proxy429`，系统托盘同理。三个平台网页控制台功能完全一致。

---

## 配置文件在哪？

首次启动自动生成默认配置（含占位 key，需改成你自己的）：

| 平台 | 配置路径 |
|------|---------|
| macOS | `~/Library/Application Support/proxy429/config.json` |
| Windows | `%AppData%\proxy429\config.json` |
| Linux | `~/.config/proxy429/config.json` |

若启动目录有 `./config.json` 则优先用它（便于在项目目录调试）。也可用 `-config <路径>` 指定。

**改配置推荐用网页控制台「配置」标签**——保存前会校验 JSON（写坏不会落盘），改完点「保存并重载」即时生效，不用重启。

## 让 Claude Code 走代理

另开一个终端：

```bash
export ANTHROPIC_BASE_URL="http://127.0.0.1:8080"
export ANTHROPIC_AUTH_TOKEN="你的 API Key"
claude
```

> 若配置里 `routes` 设了 `api` 字段，代理会用它**覆盖**客户端 token，此时 `ANTHROPIC_AUTH_TOKEN` 填任意非空串即可。
> **ARK 等只认 `Authorization: Bearer` 的上游必须用 `ANTHROPIC_AUTH_TOKEN`**（不是 `ANTHROPIC_API_KEY`，否则 401）。

## 让 Codex CLI 走代理（Responses 监听口）

Codex CLI 只说 OpenAI Responses 协议，指到本代理的 `responses_listen` 端口即可。前提：配置里 `responses_listen` 已启用（模板默认演示 `127.0.0.1:8081`；改动保存重载即生效，监听口随配置动态启停）。配置页检测到当前配置没有 `responses_listen` 时，会把下方的脚本生成区整组置灰并询问「要为本配置增加 Responses API 功能吗」——点「是，添加并保存」会自动在 `listen` 行后补一行 `responses_listen` 并保存，监听口随即启动（绝不会在没有配置时按默认地址硬生成脚本，避免本机端口被别的程序占用时 Codex 指错地方）。

### 一键配置（推荐）

**网页控制台生成命令（最省事）**：「配置」标签下方有「Codex 一键配置」区——按上方编辑框内容**实时生成**两行终端命令（地址自动取 `responses_listen`；没配置该项时生成区置灰并给出「是，添加并保存」按钮，一键补上并保存），DeepSeek 文档同款格式。默认模型下拉旁还有「上下文窗口」「压缩阈值%」两个输入框（默认 262144 / 95），会随命令烤进脚本、写进模型目录的每个条目：

- Windows：在 PowerShell 窗口粘贴 `irm '<本代理地址>/__codexsetup.ps1?...' | iex` 回车
- macOS / Linux：在终端粘贴 `bash <(curl -fsSL '<本代理地址>/__codexsetup.sh?...')` 回车

脚本由本代理按页面所选默认模型与模型目录**实时烤制下发**（完整命令以控制台实际显示为准，带全部参数），跑完重启 Codex 即生效。改了 `responses_listen` 点「保存并重载」后监听口即按新地址生效，两行命令会跟着编辑框自动更新，重新复制执行即可。已安装过再跑同一条命令走快速路径：只切换默认模型、刷新模型目录，并把 `proxy429` provider 块的名称/base_url 同步为最新（旧版脚本写入的中文名会借此升级为英文），其余配置不动。

模型下拉列出的是 `routes` 里**每个 pattern 的一个代表名**（`route.model` 自己能命中 pattern 时用真名，否则用去掉 `*` 的 pattern——本代理的 `*` 可匹配 0 个字符，这个名字必命中；纯 `*` 兜底路由固定叫 `Fallback`——它接住任意模型名，菜单里显示某个真实 model 名会误导；因此 `Fallback` 是保留名：其它路由的 `pattern` 不允许全字叫 `Fallback`（撞名的路由不生效也不进菜单，网页会红字提醒，`Fall*` 这类通配不受影响）。另外配了 `fast_route` 且带 `model` 时，菜单会多一个字面名 `fast_route` 条目，选中即走 fast 通道（等效请求带 `speed:"fast"`）；`fast_route` 同样是保留名，`pattern` 不允许全字叫 `fast_route`。脚本会把这些名字**全部**写进 Codex 的 `/model` 菜单（`model_catalog_json` 指向 `~/.codex/proxy429-models.json`），下拉选中的那个成为 `config.toml` 里的默认 `model`；之后在 Codex 里随时 `/model` 切换，走的就是对应 pattern 的路由。

**仓库脚本（交互版）**：根目录的 `codex-setup.ps1`（Windows）与 `codex-setup.sh`（macOS/Linux）是交互版（菜单选模型/地址/还原；脚本界面全英文，规避部分系统的中文编码问题），效果相同（结构参照 DeepSeek 官方 Codex 安装脚本：先备份、TOML 外科手术式改写、校验后原子落盘）：

```powershell
# Windows PowerShell
powershell -ExecutionPolicy Bypass -File .\codex-setup.ps1
```

```bash
# macOS / Linux
bash ./codex-setup.sh
```

菜单选模型（`gpt-5-codex` / `claude-fable-5` / 自定义模型名），选 9 可一键还原。脚本做的事：

- 顶层写入 `model`、`model_provider = "proxy429"`、`preferred_auth_method = "apikey"` + `forced_login_method = "api"`（这两行让 Codex 走 API-key 模式，**不要求登录官方账号**）、`model_reasoning_effort = "high"`、`model_catalog_json`；追加 `[model_providers.proxy429]` 段（token 为占位串，代理不校验）。
- 生成 `~/.codex/proxy429-models.json` 模型目录，`/model` 菜单能列出模型并切换思考档位。
- 对既有 config.toml 做外科手术而不是覆盖：清掉会与代理打架的陈旧键（`service_tier`、`openai_base_url`、context window 覆盖等，逐项报告），修正其它 provider 的 `wire_api = "chat"`（会让 Codex 起不来），`[profiles.*]` 等其余内容原样保留。
- 改前自动备份到 `~/.codex/backup-proxy429/`（含变更清单 manifest），选 9 原样还原。

装完**重启 Codex**（config.toml 不热加载）。想了解写入细节，按下面手动配置。

### 手动配置

编辑 `~/.codex/config.toml`（Windows 为 `%USERPROFILE%\.codex\config.toml`，没有就新建）：

```toml
model_provider = "proxy429"
model = "gpt-5-codex"            # 参与代理路由匹配的名字
preferred_auth_method = "apikey" # 这两行走 API-key 模式，不要求登录官方账号
forced_login_method = "api"

[model_providers.proxy429]
name = "Proxy429 Local Proxy"
base_url = "http://127.0.0.1:8081/v1"
wire_api = "responses"
experimental_bearer_token = "proxy429"
```

这套写法与 cc-switch 接管 Codex 时写入的结构完全一致（`model_providers` + `wire_api = "responses"`），只是 base_url 从它的路由端口换成本代理的。要点：

- **base_url 必须带 `/v1`、`wire_api` 必须是 `"responses"`**：Codex 会把请求 POST 到 `http://127.0.0.1:8081/v1/responses`，正是本代理的监听路径（`/responses` 也认）。
- **token 只是占位**：代理不校验它，真正的上游 key 由命中路由的 `api` 字段注入。上面两行 `preferred_auth_method`/`forced_login_method` 让 Codex 直接用 API-key 模式启动（DeepSeek 官方脚本同款写法），不会再弹官方账号登录。
- **model 名双重作用**：既参与代理 `routes` 的通配匹配（模板演示的 `gpt-5*` 路由 → DeepSeek，可按需改成别的），也用于 thinking 档位查表——想用上 adaptive thinking（见「Responses 翻译映射表」），把 `model` 直接填目标模型名（如 `claude-fable-5`），路由照常匹配转发。
- **思考档位**：config.toml 加一行 `model_reasoning_effort = "high"`（或 Codex 会话里 `/model` 调整），会作为 `reasoning.effort` 发来，按映射表翻成 adaptive effort 或 budget_tokens。
- **改完重启 Codex**：`config.toml` 是 Codex 进程启动时读取的，运行中不热加载。
- **503 且代理侧零日志 = 系统代理劫持**：Codex 会读系统代理（Windows「Internet 选项」/ macOS 网络设置）但**不认其「例外」清单**——系统代理开着时，发往 `127.0.0.1` 的请求会被送去代理服务器（那台机器的回环上没有本代理），报 `unexpected status 503 ... url: http://127.0.0.1:8081/v1/responses`，且本代理日志里看不到任何请求。唯一有效的旁路是环境变量 `NO_PROXY` 含 `127.0.0.1`——Windows 一键脚本安装时已自动检测并写入用户级 `NO_PROXY = localhost,127.0.0.1,::1`（只让本机回环绕过代理，不影响其它流量）；macOS 一键脚本自动把 `NO_PROXY`/`no_proxy` 写进 launchd 环境（`launchctl setenv`，GUI 应用与新终端窗口都生效）并安装登录项 `~/Library/LaunchAgents/com.proxy429.noproxy.plist` 保证注销/重启后仍有效（脚本选「还原」或删除该文件即可撤销）；Linux 一键脚本只做体检并给出 `export NO_PROXY="localhost,127.0.0.1,::1"` 提示，不改动系统设置；手动配置或老脚本用户自行执行 `setx NO_PROXY "localhost,127.0.0.1,::1"`（Windows），然后重启 Codex（仍不行就注销重登一次）。

验证：启动 `codex` 发一句话，代理网页控制台「状态」标签应出现一条 API 列显示 `[translate]` 的在途流，「日志」里有对应 `[路由]` 行。

### 多模型怎么配

代理侧**零改动**——`routes` 本来就按模型名通配分流，Codex 发什么模型名就走哪条路由。Codex 侧有三种方式：

- **profiles（推荐，常用几个就配几个）**：config.toml 里加 profile 段，各指定 `model`（继承顶层的 provider，不用重复写地址）：

  ```toml
  [profiles.deepseek]
  model = "gpt-5-codex"            # 命中模板的 gpt-5* 路由

  [profiles.fable]
  model = "claude-fable-5"         # adaptive thinking 查表生效
  model_reasoning_effort = "high"
  ```

  启动时选：`codex --profile fable`（不配 profile 时用顶层默认 `model`）。
- **临时指定**：`codex --model claude-fable-5`，任意名字都行，代理按名字路由。
- **`/model` 菜单列出自定义模型**：需要模型目录文件——config.toml 顶层加 `model_catalog_json = "my-models.json"`，在 `~/.codex/` 下放该文件，内容是 `{"models": [...]}`（cc-switch 就是生成这样一个 `cc-switch-model-catalog.json` 再写入这个键；条目字段可照它生成的文件抄）。不配不影响使用，只是 `/model` 菜单不列自定义模型。

## 网页控制台三个标签

- **状态**：实时统计卡片（活跃 / 等待 / 流出字节 / 速率 / 缓存命中 / 输入 / 输出 / 重试 / 分类器 / 首字延迟 / tok/s；「分类器」= 命中安全判断特征的请求数，无论是否分流、是否关思考都计，鼠标移上该卡片看明细——含「关思考」= 其中实际被改写关 thinking 的次数，点击可放大弹窗）+ 在途流列表（每个请求的 model、阶段、字节、状态码；首列状态灯 ⚪请求 / 🟡等首字节 / 🟢转发中 旁显示当前灯色已持续的秒数，只在灯变色时清零；黄灯内正在等首字节时，状态灯与总时长之间另有 `[尝试N: Xs]` = 本次尝试已等待的时长（每次尝试重新起算；重试退避中显示 `[退避中]`））。每 0.5s 刷新。缓存命中率 = cache_read / (input + cache_read + cache_creation)，与 Claude Code 的 cache hit 算法一致；点「缓存命中」卡片可看按上游模型分组的明细（含缓存写入量）。中途断开的流（按 Esc 中断生成等）不计入聚合——它们拿不到真实用量拆分，计入会污染命中率，日志里标 `[中断]`，完成流状态码记 499（口径与上游提供商后台一致：上游响应没发完连接就结束了——最常见是下游主动取消，取消会传导成上游断连；上游完整发完后下游才断开的，如 Codex 收完即关连接，仍记 200）；状态码列中非 200 的状态码加方括号显示（如 [499]、[400]），一眼挑出异常流；重试/预算用尽的流代理会向下游透传兜底 error 事件（overloaded_error），状态码列显 [重试尽]；发生过退避重试的流在状态码后追加金色 [重试N次]（N = 重试次数，如 200[重试2次]；[重试尽] 时同样带，可对照 max_retries 看是否打满）。在途流（随转发实时增加）与最近完成流的 model 列后都会以 `[Read*1][Edit*3]` 形式（金色）列出该流响应中调用过的工具——`web_search` 等服务端工具也计，按首次出现顺序；同名 N 次合并显 `*N`（原始次数），单次调用显 `*1`，参数结构体为空的单次调用显 `*0`（如 Kimi 空搜索的无参调用——一眼区分空搜索与真搜索）。剥过回放搜索块的流另有红色 `[剥N]`（N = 剥块总数）：在途流挂 model 列，最近完成流挂缓存命中率后（如 `81%[剥2]`）；其中多少是对话水位剥的、多少是上游 400 兜底剥的，拆分看日志 `[剥块]`/`[兜底]` 行。model 列带 `[count_tokens]` 前缀的流是 Claude Code 的 token 计数探针（`/v1/messages/count_tokens`，做上下文长度估算），其原始内容只有 `{"input_tokens":N}` 属正常，不计入任何 token 统计。点击在途流/最近完成流的行可回看该流：默认看输出（「显示解析/显示原始」切换）；「看请求体」回看导致这个流的下游请求体（JSON 自动美化，非完整 JSON 按原文显示）。浏览一律只给前 256KB；勾选「储存完整结构体」（默认关，重启复位）后，新开始的请求额外记录完整请求体与输出（不设上限，占内存），查看器出现「下载请求体/下载输出」按钮可下载完整文件（JSON 美化后保存，非 JSON 按原文），以及「交互式JSON」按钮——把请求体/输出渲染成可按键折叠展开的 JSON 树（默认全部折叠，点键名行懒展开；输出是 SSE 事件流时解析成事件数组再成树），取消勾选立即清空已存的完整副本、下载与交互按钮消失。数据残缺的流不会静默当成完整版：请求体只剩截断版的「下载请求体」置灰（悬停见原因），无完整输出副本的「下载输出」置灰，交互式JSON 对这两类直接提示不看。Responses 翻译口的流记录的是翻译成 Anthropic 后的请求体。最近完成流表另有「缓存年龄」列：按会话+路由显示该会话该路由最近一次缓存写入距现在过了多久（`m:ss` 递增；上游缓存真实存活期是动态的，这列不再猜倒计时，只说明这份缓存是多久前写的，还能不能用请对照「缓存命中」弹窗的实测区间判断）。同会话同路由的最新一条流显示年龄，被更新的同键流刷新后旧行显示 `-`，无会话标识的流恒 `-`；年龄从流开始时刻起算，且开始时刻距今 5 分钟内的「会话+路由最新一条」不会被「保留完成流 N」挤出列表（行数可因此超 N）。在途流与最近完成流表的「API」列把协议来源与思考值合一格：名 = 协议来源（橙 `[Anthropic]`=Anthropic 口原生、紫 `[translate]`=Responses 口翻译），名后 `[值]` = **实际发给上游**的思考配置最短形态（翻译映射、分类器关思考等代理改写全部生效后的最终口径），**其颜色 = 词汇口径**（思考是针对上游的：上游收到的都是 Anthropic 格式，所以紫名后跟橙值）——橙=Anthropic thinking（直连原样或翻译映射后）；`关`=thinking 关或 effort none/off、`开 N`=enabled+budget_tokens N、`adaptive`=自适应无档、`low`/`high`/`max` 等档位词=adaptive 的 effort、无 `[值]`=请求体未带思考字段；如 Codex 发 effort high 翻译到 Anthropic 上游显 `[translate][开 16384]`（紫名橙值）。黄灯（等待首字节）阶段被下游断开的 499 流不刷新缓存（本行显 `-`，锚停留再上一次同键流）；绿灯（流式中）断开的 499 照常刷新；同会话同路由有在途流正在吐字时，该键最新完成行冻结显示 `[m:ss]`（方括号内为刷新那一刻旧锚的年龄，数字不变；列头问号有悬停说明），新锚等该流完成后生效。点击「缓存命中」卡片，弹窗底部「实测缓存时间」表列出各上游实测的缓存存活时间（模型、URL、下界 ≥、≥形成、上界 <、<形成、观测次数七列）：按 URL+模型名归为一类（不看其他参数），同会话相邻两条流后条命中率 ≥95% 记一次区间下界「至少活了间隔那么久」（取最大值），前条命中过而后条命中率 <50% 记一次区间上界「没活过间隔那么久」（取最小值；不看严格归零——系统提示词等公共前缀的残留缓存命中不算活着）；输入总量不足 1024 token 的流不观测；两侧观测矛盾时（上游缓存时间中途变化或被提前驱逐）以较新的观测为准、被否的一侧作废重测、观测次数同步归零重计；「≥形成」「<形成」两列 = 各自界数值形成至今的时长（m:ss 递增），该界数值变化（含作废重测）即重新起算，只新增支撑观测、数值不变时不重置，无该界观测时随界同显 -；实测只作展示，纯内存态，重启或清空统计即清零。「清空统计」按钮清空上述累计统计与最近完成的流列表（在途流与流的 # 编号不清；内存日志另有「清空日志」按钮）。
- **日志**：实时滚动日志 + 最近 500 行历史，滚轮翻历史，自动滚到底。每条请求会打路由走向，如 `[路由] #1 claude-opus-... -> https://... (model ... -> kimi-for-coding)`、`[路由] #2 搜索兜底 ... -> deepseek-v4-flash`。
- **配置**：直接编辑 `config.json` 内容，**保存并重载**（校验+落盘+生效）/ **仅重载**（只重新读盘）。

管理端点（`/__logs`、`/__config`、`/__reload`）**永远只限本机**访问（非 `127.0.0.1`/`::1`/`localhost` 请求返回 403），即使代理 `listen` 在 `0.0.0.0` 也不会泄露日志/配置。

### 访问控制

转发通道与管理端点都**永远仅本机可连**——即使误把 `listen` / `responses_listen` 设成 `0.0.0.0` 监听所有网卡，非本机请求也一律被 403 挡掉，局域网设备用不了代理、看不到日志/配置。没有开关，无需配置。

## 路由配置（按模型 / 能力分流）

`routes` 按 Claude Code 发的 model 名**通配匹配**（`*` 匹配任意长度任意字符）把请求分流到不同上游，命中后可改 `url` / `api` / `model`：

```json
"routes": [
  { "pattern": "*opus*",   "url": "https://上游A", "api": "sk-aaa", "model": "强模型" },
  { "pattern": "*haiku*",  "url": "https://上游B", "api": "sk-bbb", "model": "便宜模型" },
  { "pattern": "*",        "url": "https://上游A", "api": "sk-aaa", "model": "强模型" }
]
```

按数组顺序匹配，第一个命中的生效——宽通配会截胡窄通配，更具体的 pattern 要写在前面（如 `*opus-4*` 要在 `*opus*` 前），`*` 兜底放最后。

**能力兜底**（请求需要某能力但命中的上游不支持时，自动改走兜底上游）：

- `text_only: true` —— 该模型只支持纯文本；请求**带图片**时改走 `multimodal_fallback`（没配则透传原模型）。
- `no_search: true` —— 该上游不支持搜索；请求**带搜索工具**时改走 `search_fallback`（没配则透传原模型）。
- `classifier_route` —— 分类器（安全判断）请求专用路由，甩到便宜模型省主模型额度。
- `fast_route` —— `"speed":"fast"` 请求专用路由。

**搜索摘要模式**（`search_fallback` 专属）：配 `"summary_mode": true` 后，搜索请求不再整请求转走兜底上游，而是代理分两步自建 Kimi 格式响应返回：step1 搜索拿 `web_search_tool_result`（标题/URL），step2 流式生成详细摘要，拼成标准 SSE 流返回客户端（下拉列表 + 模型回答都可用），不调用主力。摘要详细程度用 `"summary_level"` 控制：`low`（默认，简短）/ `mid`（中等）/ `high`（详尽）/ `max`（在 high 基础上，遇到步骤/方法/代码/公式完整逐字复述）；`"summary_thinking": true` 可让 step2 开 thinking。step1/step2 失败自动降级为整请求转走。搜索触发时状态页会显示「搜索step1·模型」「搜索step2·模型」两条子流。详见 README.md「搜索摘要模式」。

**增强搜索**（`routes` 条目内配 `"enhance_search": {...}`）：与上面相反的场景--主力本身支持搜索（`no_search` 不为 `true`），但你不想用主力自带搜索，想让代理用 kimi 摘要模式回答。带搜索工具的请求不调主力，改用**该 route 自己的 `url`/`api`/`model`** 走 step1 搜索 + step2 摘要 + 自构响应，参数用该 route 的 `enhance_search.summary_level`/`summary_thinking`。与 `search_fallback.summary_mode` 互斥（`no_search:true` 走 search_fallback，`no_search:false` + `enhance_search` 走增强搜索）。详见 README.md「增强搜索」。

四个兜底字段都是可选的，按需配。完整字段说明见项目根 `README.md` 和 `config.example.json`。

**全局流式化**（顶层配 `"convertAlltoStream": true`）：把**所有非流式请求**（`stream:false` 或省略）悄悄改成流式发给上游。好处：分类器、搜索 step1 这类原本"一次性返回"的请求，也能在网页控制台实时看到吐字、统计首字延迟与 tok/s。请求方完全无感知——代理把流完整收完后，重建标准非流式 JSON 一次性返回，Claude Code 拿到的还是它预期的非流式响应。流中途断开会自动整体重试；路由改写过 model 的会回写原 model。详见 README.md「全局流式化」。

**Responses API 监听口**（顶层配 `"responses_listen": "127.0.0.1:8081"`，空 = 不启用；配置模板默认演示开启）：额外开一个 OpenAI Responses API 端点，把 Codex CLI 等只说 Responses 协议的工具接到 Anthropic 上游——请求翻译成 Anthropic 走主管线（路由/重试/网页监控照常），响应翻译回 Responses（流式事件流或一次性 JSON）。工具里的 model 名照常参与路由匹配，配一条 `gpt-5*` 路由即可指定上游。改动保存重载即生效（监听口动态启停）。另外，翻译层会自动删除 Kimi（k3-256k 等）响应里以「Search results for query:」开头的搜索回声行（连同后面的 query 一起删；转发给客户端与回放给上游的历史同套规则，防止回声在上下文里累积、诱发连续同类搜索），剥完为空的文本块与无参空调用、空结果等空搜索结构也不会出现；前言被模型多条重复模仿、粘在正文开头时仍会剥光前言留下正文。Codex 界面不再堆这类回声行；真实搜索以结果链接照常显示。详见 README.md「Responses API 监听口」。

**关思考请求悄悄升级 low**（顶层配 `"translateNone2Low": true`，默认 false，仅 Responses 翻译口生效；透传流与 Anthropic 口不改写）：下游发来关思考（`reasoning.effort` 为 none/off/disabled）的翻译请求时，代理悄悄升级为 low 思考发上游——adaptive 模型给 `{"type":"adaptive"}` + `output_config.effort:"low"`，budget 模型给 `{"type":"enabled","budget_tokens":2048}`（压顶 max_tokens 一半，容不下 1024 下限则放弃升级保持关闭）——回传时剥离思考块，下游看到的仍是关思考响应，token 用量如实透传。动机：Kimi 文档「关闭 thinking 后路由到 K2.8 Preview 无思考版：K3 系列与 K2.8 Preview 关闭 thinking 后，请求均由 K2.8 Preview（无思考）处理」，开着 low 避免 K3 被降级路由。工具续轮（末轮无签名思考块可回放）同样升级；上游若拒思考（200 流内错误含 thinking 字样）自动把 thinking 改回 disabled 重试一次，不烧退避预算；强制 `tool_choice` 与思考互斥时放弃升级、保留工具约束。状态页 API 列显双色徽标 [off->low]（off 取 [translate] 紫 = 下游口径，low 取 Anthropic 橙 = 上游口径），兜底回退后如实回显 off。

**状态页「看请求体/看返回体」的数据源**：看请求体 = 下游→代理的请求体原文（客户端发给代理的）；看返回体 = 代理→下游的回传流（客户端实际收到的）。不是代理→上游的请求体/响应体——上游侧是代理内部实现，对用户是黑盒。观测点设在客户端视角的边界上：用户想知道的是「我发了什么、我收到了什么」。

## Responses 翻译映射表

`responses_listen` 端口把 OpenAI Responses 协议翻译成 Anthropic Messages 协议。翻译规则与 cc-switch 3.20.0 完全一致，本页汇总所有映射，方便对照客户端（Codex CLI 等）发的东西最终变成什么。

### 模型分类表（thinking 行为按客户端发来的 model 名查表）

匹配规则：模型名转小写、`.` 和 `_` 换成 `-` 后做子串匹配（如 `anthropic/claude-opus-4.8`、`claude_opus_4_7` 都能命中 `opus-4-8` / `opus-4-7`）。**注意查表用的是客户端发来的 model 名，发生在路由改写之前**——若路由会把 `gpt-5-codex` 改写成 `claude-fable-5`，想让下表生效，客户端的 model 直接填目标模型名（路由照常匹配转发）；反过来，客户端名命中下表但**路由目标模型**能力不一致时（如别名叫 `claude-fable-5` 实际路由到只支持 budget 的 Kimi），在该路由条目配 `"thinking": "budget"`（强制 `enabled+budget_tokens`）或 `"adaptive"`（强制 `adaptive+effort` 档位）覆盖判定，省略或 `"auto"` 维持查表。该参数只对 Responses 翻译流生效（透传流不翻译、Anthropic 口不改写客户端的思考字段），填其他值配置加载报错。

| 分类 | 命中的模型名子串 | 含义 |
|---|---|---|
| adaptive 模型 | `fable-5`、`mythos-5`、`mythos-preview`、`sonnet-5`、`opus-4-8`、`opus-4-7`、`opus-4-6`、`sonnet-4-6` | thinking 用 `{"type":"adaptive"}` + `output_config.effort` 表达，不用 budget_tokens |
| 默认开 adaptive | `fable-5`、`mythos-5`、`mythos-preview`、`sonnet-5` | 客户端不带 reasoning 参数也开 adaptive（其余 adaptive 模型要带 effort 才开） |
| 关不掉 thinking | `fable-5`、`mythos-5` | 拒绝 `thinking:disabled`：客户端显式 `effort:"none"` 时改成 adaptive + `effort:"low"`；与强制 tool_choice 冲突或历史缺签名 thinking 时直接报错 |

不在表里的模型（如 `gpt-5-codex`、`deepseek-*`、`kimi-*`、`claude-sonnet-4-5` 及更早）走下面的 budget_tokens 路径。

### reasoning.effort 映射

客户端 `reasoning.effort` 按模型分类走两条路径（不识别的值当作没带）：

| effort | 非 adaptive 模型 → `thinking.budget_tokens` | adaptive 模型 → `output_config.effort` |
|---|---|---|
| `minimal` / `low` | 2048 | `low` |
| `medium` | 8192 | `medium` |
| `high` | 16384 | `high` |
| `xhigh` / `max` / `ultra` | 24576 | `max` |
| `none` / `off` / `disabled` | 不开（`thinking:disabled`） | 能关的模型 `thinking:disabled`；关不掉的（fable-5/mythos-5）仍 adaptive + `effort:"low"` |
| 不带 | 不开 | 默认开 adaptive 的开（无 output_config），其余不开 |

budget_tokens 还有两条保护：压到 `max_tokens` 的一半（给可见回答留空间），压完不足 1024 则不开。`max_output_tokens` → `max_tokens`，缺省 32000。

### thinking 与历史、工具选择的相互作用

- **工具续轮校验**：开 thinking 要求最后一轮如果是工具结果（tool_result），其紧邻的上一条 assistant 必须带回放的签名 thinking 块（客户端回放 reasoning 信封即可自动满足）。不满足时：关不掉的模型报错 400；能关的 adaptive 模型本请求改 `thinking:disabled`；其余模型本请求不开 thinking（即使带了 effort）。
- **强制 tool_choice 冲突**：thinking 开启时 Anthropic 拒绝 `tool_choice` 为 `required`/指定工具。处理：关不掉的模型报错 400；其余模型本请求关掉 thinking（并恢复 temperature/top_p 透传），tool_choice 原样保留。
- thinking 开启时 `temperature`/`top_p` 不透传（与 Anthropic 互斥规则一致）。

### 工具与输入项映射

| Responses 侧 | Anthropic 侧 | 备注 |
|---|---|---|
| `function` 工具 | `tools[]`（name/description/input_schema） | |
| 字符串形式工具 / `custom` 工具 | 包装成 `{"input": string}` 单参数 schema，原始定义嵌进 description | 模型产出 `custom_tool_call`，item id 前缀 `ctc_`；流式中途不吐 arguments，结束时一次性发原文 |
| `namespace`（MCP）工具 | 子工具拍平成 `ns__name`；超 64 字节截断 + `__` + 8 字节哈希 | 回放时反解还原 `namespace` 字段 |
| `tool_search` | 固定代理工具（query/limit） | 产出 `tool_search_call`（execution=client） |
| `web_search` / `web_search_preview` | `web_search_20250305` | cc-switch 会丢弃，本代理保留映射 |
| `input_file`（file_url / file_data） | `document` 块（url / base64 source） | 默认 `application/pdf`；file_id 引用等认不出的形态序列化成文本兜底，不静默丢 |
| `input_image`（data URL / http URL） | `image` 块（base64 / url source） | blob:/file: 等认不出的形态序列化成文本兜底，不静默丢 |

| `reasoning.encrypted_content`（本代理信封） | 还原签名 thinking 块 | 前缀 `p429-ant-thinking-v1:`，别家/乱码信封丢弃 |
| `reasoning.encrypted_content`（搜索信封） | 还原成对的 `server_tool_use` + `web_search_tool_result` 搜索块 | 前缀 `p429-ant-search-v2:`；信封带上游 url+key 哈希归属（另记模型名供排查），整个 payload 用 api key 派生掩码异或混淆——客户端历史里不躺明文 url/key 信息，key 不对解不开自然跳过（换 key 旧信封自动作废）；url 不同源也跳过（解不开，省 token），跨模型不拦（实测照常解密）；封入时调用块 id 已归一为结果块的注册 id（Kimi 流式给的 `tool_` id 注册表不认，原样回放必 400）；信封带封入时刻——不设固定存活期上限（实测封入 1.7 小时的 id 仍存活）；还原后上游仍报搜索 id 过期（旧对话的搜索块有存活期）时代理自动剥掉回放搜索块重试一次，无感降级为重新搜，并记最老被剥信封的封入时刻为该对话水位（只升不降），此后不比水位新的信封直接不还原（主动剥，不撞 400；注册表按龄淘汰，同龄与更老的必死）；无 ts 老信封视同最老：有水位剥、无水位乐观还原 |
| `web_search_call`（历史回放的调用项） | 不上行（丢弃） | 纯客户端展示件：id 是代理自造、上游搜索注册表从未登记，上行必 400 并连坐信封还原的真搜索对被一起剥掉（生产实证）；搜索内容只由上面的搜索信封回放 |
| `parallel_tool_calls: false` | `tool_choice.disable_parallel_tool_use` | 无 tool_choice 时补 `{"type":"auto"}` |

usage 映射：`input_tokens`、`output_tokens` 直译；`cached_tokens` → `cache_read_input_tokens`；`cache_write_tokens` → `cache_creation_input_tokens`（另留同名兼容别名）；`reasoning_tokens` → `thinking_tokens`。

## 排错

- **Claude Code 没走代理**：必须在跑 `claude` 的同一个终端里先 `export` 再 `claude`；`echo $ANTHROPIC_BASE_URL` 应输出 `http://127.0.0.1:8080`。
- **端口被占**：「配置」标签改 `listen` 后保存重载**不会**重新监听端口（监听只在启动时绑定），需退出代理重启。
- **代理起不来 / 网页控制台打不开**：多半是 `listen` 端口冲突或配置有误。此时网页不可用，直接编辑上面的配置文件路径，改好 `listen` 后重启。排查启动错误可临时设 `"log_file": "proxy.log"` 把日志落盘。
- **看不到重试日志**：「日志」标签会显示 `[尝试 N] 上游响应状态码: 429` -> `状态码 429，等待 ... 后重试`。
- **想留存日志**：配置里设 `"log_file": "proxy.log"`；默认只留内存（500 行环形缓冲供网页查看），不落盘。
- **启动后看不到任何窗口**：这是预期的——程序纯托盘运行，看状态点菜单栏/托盘图标的「查看日志」。

bash build.sh                                  # 当前平台：macOS 出 .app，Windows 出 .exe，Linux 出二进制
GOOS=darwin  GOARCH=amd64 bash build.sh        # Intel Mac（仍出 .app）
GOOS=windows GOARCH=amd64 bash build.sh        # Windows x64
GOOS=linux   GOARCH=amd64 bash build.sh        # Linux x64
