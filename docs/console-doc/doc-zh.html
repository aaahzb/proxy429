这是什么

Proxy429 是一个跑在本机的 Anthropic 兼容代理。AI 客户端把请求发给它，它再转发给一个或多个上游，并把过程完整显示在网页控制台里。

它主要做三件事。

  • 扛住 429 和 5xx：按指数退避自动重试，客户端通常感觉不到上游抖动。
  • 按模型名分流：用 routes 把不同模型名的请求送到不同上游和不同 key。
  • 协议翻译：把 Codex CLI 的 OpenAI Responses 请求翻译成 Anthropic Messages，让 Codex 也能用 Anthropic 上游。
Claude Code ── Anthropic ──▶ 127.0.0.1:8080 ┐
Codex CLI   ── Responses ──▶ 127.0.0.1:8081 ┴─▶ routes / 兜底 ──▶ 上游

控制台地址是 http://127.0.0.1:8080/__logs，状态、日志和配置都在里面。所有监听口都只接受本机连接。

快速上手

  1. 启动代理。Windows 双击 proxy429.exe；macOS 双击 Proxy429.app（首次被 Gatekeeper 拦截时右键选「打开」）；Linux 运行 ./proxy429。启动后只有托盘或菜单栏图标，没有窗口。
  2. 打开控制台。点托盘菜单「查看日志」，或直接访问 http://127.0.0.1:8080/__logs。
  3. 接 Claude Code。在与 claude 同一个终端里执行： 
    export ANTHROPIC_BASE_URL="http://127.0.0.1:8080"
export ANTHROPIC_AUTH_TOKEN="your API key"
claude
    路由条目带 api 时，这里的 token 可以填任意非空串，真实 key 由代理注入。只认真实 Authorization: Bearer 的上游（如火山 ARK）必须用 ANTHROPIC_AUTH_TOKEN，不能用 ANTHROPIC_API_KEY，否则会 401。
  4. 接 Codex CLI。先在配置页确认 responses_listen 已启用，再到配置页底部的「Codex 一键配置」，复制对应系统的命令执行，然后重启 Codex。细节见「Codex 与 Responses 翻译」。

验证：状态页的「在途流」出现请求，日志页出现 [route] 行，就说明链路通了。

配置文件在哪：首次启动会在用户目录生成一份带占位 key 的配置。

平台路径
Windows%AppData%\proxy429\config.json
macOS~/Library/Application Support/proxy429/config.json
Linux~/.config/proxy429/config.json

启动目录下有 ./config.json 时优先用它，调试很方便。也可以启动时加 -config <路径> 指定文件。日常修改建议走控制台的「配置」页。

界面导航

顶部有「状态」「日志」「配置」三个标签。右侧是「文档」按钮和语言切换。关闭浏览器标签页只是隐藏控制台，代理继续运行。

  • 状态：统计卡片、在途流、最近完成的流。点任意一行可以查看该流的请求体和输出。卡片和徽标的含义见「状态页与统计」和「徽标词典」。
  • 日志：实时滚动日志。内存只保留最近 500 行，需要留存请配置 log_file。
  • 配置：直接编辑 config.json，保存后立即生效。见「修改配置」。

修改配置

配置页可以新建、重命名、删除和切换配置文件，文件列表每 3 秒自动刷新。当前生效的配置不能删除。

保存并重载会先校验 JSON，再把文件写盘并立即生效。仅重载只是从磁盘重新读取，不改文件。校验不通过时不会写盘，错误会指出具体位置。

listen 只在启动时绑定。修改主监听端口后要退出并重启代理。responses_listen 例外，保存后监听口随配置即时启停。

共享变量 vars

多个路由用同一个 key 时，把 key 写进顶层 vars，路由里用 $NAME 或 ${NAME} 引用。换 key 只改一处。

"vars": { "DEEPSEEK_KEY": "sk-..." },
"routes": [
  { "pattern": "*opus*", "url": "https://api.deepseek.com", "api": "$DEEPSEEK_KEY", "model": "deepseek-v4-pro" }
]
  • 文件里任意字符串值都可以引用变量，api 和 url 都行。文件保留引用原文，加载时再解析。
  • 引用未定义的变量会拒绝加载或保存，并给出路径，例如 routes[0].api。
  • 变量值必须是字符串，空串也算。变量可以再引用变量，只支持一层。
  • $ 后面不是合法名字时原样保留，例如 $5。

预览 lazyApply

配置页的「预览 lazyApply 生效后 JSON」只读展示补完默认值后的配置，不会写盘。「复制到编辑框」把结果放回编辑器，仍需自己保存。规则见「全局默认 lazyApply」。

访问控制：转发口和管理端点（/__*）永远只接受本机连接。即使把 listen 写成 0.0.0.0，局域网设备也连不上，也看不到控制台。

路由基础

routes 按模型名通配匹配。* 匹配任意长度的任意字符，也可以匹配空串。命中后，url、api、model 三项会覆盖请求。

"routes": [
  { "pattern": "*opus*",  "url": "https://upstream-a", "api": "sk-aaa", "model": "strong-model" },
  { "pattern": "*haiku*", "url": "https://upstream-b", "api": "sk-bbb", "model": "cheap-model" },
  { "pattern": "*",       "url": "https://upstream-a", "api": "sk-aaa", "model": "strong-model" }
]
  • 顺序决定结果：按数组顺序匹配，第一个命中的生效，没有「更具体优先」。*opus* 写在 *opus-4* 前面时，claude-opus-4-8 只会命中前者。具体规则写在前面，* 兜底放最后。
  • pattern 可以写数组："pattern": ["*fable*", "*opus*"] 等价于把同一条路由复制多份，每份一个 pattern。其余字段共享，位置和数组顺序就是匹配顺序。空数组或非字符串成员会在加载时报错。
  • 保留名：纯 * 兜底路由在 Codex 菜单里固定叫 Fallback，fast 通道叫 fast_route。任何 pattern 不能整串正好等于这两个名字，撞名的路由不生效也不进菜单；pattern 是数组时只禁用撞名的那一项，其余成员照常生效。Fall* 这类通配不受影响。
  • effort 钉住思考档位：路由写了 effort（low/mid/high/max，mid 按 medium 发给上游）时，在钉住点（路由落定后、搜索改写与原生 off->low 升级之前）请求体顶层 thinking 为 adaptive 的，代理把顶层 output_config.effort 强制改成该档位，客户端原本的档位被忽略；已经是该档位的不动也不出徽标。请求体不是 adaptive 形态（budget、关思考、没有 thinking 字段）时一个字节都不动，明确关思考永不被钉住（convertOff2Low 的静默升级在两个口都保持自己的 low），不写 effort 也完全不动。只有真正服务的路由算数：分类器、fast、图片和搜索兜底、Responses 透传各走各的路。状态页 API 列用青绿 [from->to] 徽标显示最后一次改写的前后值（更晚的搜索改写拥有徽标；400 兜底回关思考时徽标清空）。状态页模型列同时显示配置档位：原始模型 -> [档位] 目标模型，模型未被改写时附在原名后成 原始模型 [档位]（如 claude-fable -> [high] deepseek-flash）；档位用上游词汇（mid 显示为 medium），请求体未被改写也照样显示——是否真的改写过看 API 列徽标。顶层 compactEffort（low/mid/high/max）对上下文压缩请求（Claude Code 的 compact、Codex CLI 的 checkpoint compaction）做同样的钉档，而且优先级高于路由 effort：压缩请求一律用 compactEffort 的档位，路由钉住的档位在这些请求上让位；未设置时行为与原来完全一致。压缩流的模型列用 compactEffort 档位占据 [档位] 槽位（被覆盖的路由 [档位] 换成 compactEffort 档位，即 原始模型 -> [档位] 目标模型 的同一位置），实际改写过同样看 API 列的 [from->to] 徽标。

命中了哪条路由，看日志的 [route] 行，或状态页 model 列的 [Pattern]、[分类器]、[Fast]、[多模态]、[搜索] 前缀。

能力兜底

命中一个路由后，如果上游缺少请求需要的能力，代理会自动换到兜底上游。搜索和图片的处理顺序不同。

  • 搜索请求（带 web_search 工具）：命中的路由标了 no_search 时，整条请求转给 search_fallback，由兜底上游自己搜索和回答。没配 search_fallback 就透传原路由，上游可能报错。
  • 图片请求（不含搜索）：命中的路由标了 text_only 且请求里含图片时，转给 multimodal_fallback。没配就透传原路由，上游可能不认图片。
  • 搜索优先：同时带搜索和图片的请求一律按搜索处理，走 search_fallback。

兜底路由也使用 url/api/model 结构，并支持部分行为字段，例如 thinking 和 convertOff2Low。发生兜底后，生效的是兜底路由自己的字段；搜索类字段按逐字段规则覆盖，详见「参数总表」。

想让支持搜索的上游自己做搜索加摘要，见「搜索增强与空搜守卫」。想把分类器请求或 fast 请求单独分流，见「专用路由」。

专用路由

classifier_route

Claude Code 的安全判断和 Codex 的审批评估会发出特征请求。命中特征的请求无视原模型，直接走 classifier_route，适合甩给便宜模型，省主模型额度。

  • classifier_thinking 可选 off、low 或不写。不写就保持请求原样。off 把请求改写成关思考，分类返回更快。low 先关思考，再按 convertOff2Low 的机制悄悄升级成 low 发给上游，回传剥掉思考块，客户端无感。
  • classifier_thinking_cc 和 classifier_thinking_codex 按来源分别覆盖共享值。
  • 分类器请求的 max_tokens 很小（guardian 可能只有 64）。low 策略需要 1024 token 地板时，代理会在上游侧把 max_tokens 增加 1024 来补足，客户端无感。

整体顺序：分类器特征请求先走 classifier_route，带 "speed":"fast" 的请求再走 fast_route，其余按 routes 通配匹配，最后落到 upstream。

状态页的「分类器」卡片统计命中数，悬停看分来源明细，点击放大。

fast_route

请求带 "speed":"fast" 时走 fast_route。Claude Code 的 /fast 和 Codex 菜单里的 fast_route 项都会触发。命中后代理会给响应补上快速的限流头，让客户端保持快速模式。

全局默认 lazyApply

lazyApply 是一个全局默认值包。它只给路由类对象本来就支持的字段补值，效果等同于把该键写进每个没有显式设置它的对象。它不会新增字段，也不会创建未配置的可选路由。

  • 逐字段优先级：局部显式值（包括 false 和空串）> lazyApply > 内置默认。
  • 连接三件套可继承：url、api、model 会从 lazyApply 继承（加载时写进每个省略该键的对象），所以上游只写一次，路由可以简化成 {"pattern": "*sonnet*", "effort": "high"}，fast_route 甚至可以写成 {}。局部写了的连接键仍然优先；写空串即停止继承："api": "" 透传客户端 token、"model": "" 不改模型，"url": "" 表示不换上游——routes 条目照常生效并转发默认 upstream，classifier_route 只做思考改写，fast_route / multimodal_fallback / search_fallback 不启用、请求走正常路由。pattern 与 url_response_api 不继承，永远逐对象写。
  • effort 只能逐路由写：routes[] 的 effort 钉住不参与继承，lazyApply 不提供这个字段，避免一个全局默认把所有路由的档位一起钉死。顶层 compactEffort 是唯一的全局档位设置，但它只影响上下文压缩请求，不会碰其他流量。
  • enhance_search 整体覆盖：局部写了就整块生效，不会和 lazyApply 里的对象合并。
  • 个别对象可以退出：在对象里写 "noLazyApply": true，它就不继承任何默认值，自己显式写的字段照常生效。
  • 会参与优先级链：继承来的 claudeSearch* 视同局部写入，会压过 search_fallback 自己的值。想用 fallback 的值，就在该路由上写 noLazyApply。

受支持的字段见「参数总表」的 lazyApply 一节。配置页的预览按钮可以只读核对展开结果。

连接与重试

  • listen：Anthropic 主监听地址，模板是 127.0.0.1:8080。只在启动时绑定。
  • upstream：默认上游。没命中任何路由时用它。如果配置了纯 * 兜底路由，可以不写。
  • responses_listen：OpenAI Responses 监听地址，空表示关闭。保存后立即启停。
  • 重试参数：max_retries 是最大重试次数，不含首次尝试。base_delay_s 是首次退避秒数，之后按 2 的幂递增，并叠加最多 30% 的随机抖动。max_delay_s 是单次退避上限，写 0 会把退避截成 0，等于不等待。total_budget_s 是整条请求的重试总预算。retry_status_codes 列出触发重试的上游状态码，空数组等于不按状态码重试。
  • respect_retry_after：上游返回 Retry-After 头时优先按它等待。
  • upstream_header_timeout_s：等待上游首字节的上限。超时按内部重发处理，不写等于 70 秒。
  • ping_interval_s：重试等待期间发给客户端的 SSE 保活间隔，不写等于 5 秒。非流式请求不发送保活。

重试用尽时，代理会向下游发一个 overloaded_error 事件。状态码列显示 [重试尽]；发生过退避重试的流显示 [重试N次]。

日志相关：log_request_detail 记录请求体细节；log_file 把日志追加到磁盘文件；recent_sample_window 是状态行「首字」和「tok/s」的最近样本窗口，不写等于 20。

Codex 与 Responses 翻译

把顶层 responses_listen 设为 127.0.0.1:8081 后，代理会在这个地址额外提供 /v1/responses。Codex CLI 只懂 OpenAI Responses 协议，请求会先翻译成 Anthropic Messages，走和 Claude Code 完全相同的主管线，再把响应翻译回 Responses。

接入 Codex

最省事的方式是配置页底部的「Codex 一键配置」。两行命令按上方编辑框实时生成，自动备份并改写 ~/.codex/config.toml，还会写模型目录。下拉选「（还原默认 Codex 配置）」得到的命令可以撤销。改完重启 Codex。

手动配置如下。

model_provider = "proxy429"
model = "gpt-5-codex"
forced_login_method = "api"

[model_providers.proxy429]
name = "Proxy429 Local Proxy"
base_url = "http://127.0.0.1:8081/v1"
wire_api = "responses"
experimental_bearer_token = "proxy429"

base_url 必须带 /v1，wire_api 必须是 responses。token 只是占位，代理不校验，真实 key 由命中路由的 api 注入。

Codex 报 503 且代理侧零日志：系统代理把发往 127.0.0.1 的请求劫走了。让 NO_PROXY 包含 127.0.0.1 后重启 Codex。Windows 和 macOS 的一键脚本会自动写入并持久化，Linux 脚本会给出提示。

模型名与思考映射

Codex 发来的 model 名照常参与 routes 匹配。思考形态的查表用的是客户端原始 model 名，发生在路由改写之前。想让映射表生效，就把 Codex 的 model 直接填成目标模型名。

模型分两类。adaptive 类按 thinking:adaptive 加 output_config.effort 表达思考，包括 fable-5、mythos-5、mythos-preview、sonnet-5、opus-4-8、opus-4-7、opus-4-6、sonnet-4-6。其余模型按 budget_tokens 表达。

识别不了的值按「不带该字段」处理。budget_tokens 还有两道保护：不超过 max_tokens 的一半，封顶后低于 1024 就不开启。max_output_tokens 默认 32000。

当别名命中了 adaptive 表，实际路由目标却只支持 budget（例如别名叫 claude-fable-5，实际接到 Kimi），在该路由条目上写 "thinking": "budget" 或 "adaptive" 纠正。这个字段只对翻译流生效。

思考、历史与信封

  • 开着思考时，工具续轮的历史必须带可回放的签名思考块。allowNoThinkBlock4Anthropic 默认 true：先按所请档位照发，真被上游 400 才自动关思考重试一次，并且不剥思考块，让下一轮历史自愈。写 false 则一开始就关思考。
  • 强制 tool_choice 与思考互斥。能关思考的模型会关掉这次请求的思考并保留工具约束；fable-5、mythos-5 关不掉，直接报错。
  • 思考块和每次搜索的完整结果会被封进响应里的信封，下一轮客户端回放时还原，思考链和搜索正文都能继续用。搜索信封按上游和 key 混淆，换 key 或换上游后自动失效，客户端历史里不出现明文 URL 或 key。
  • 旧对话的搜索块在上游过期时，代理会剥掉回放块并重试一次，无感降级为重新搜索。剥离数量显示为 [剥N]。

搜索增强与空搜守卫

Claude Code 每次网页搜索会单独起一个子代理请求。独立搜索请求的判定标准是：最后一条 user 消息以 Perform a web search for the query 开头。只看最后一条，历史里引用这句话不算。命中判定的请求在 model 列显示青绿色 [Search]。

让上游自己写摘要：enhance_search 与 claudeSearchSummary

enhance_search 配在 routes 条目上，并且该路由没有标 no_search 时生效。代理把摘要指令注入搜索请求本身，仍走该路由自己的上游，一次请求完成搜索和逐条摘要，响应原样透传。旧的 summary_level 控制详细度（low、mid、high、max），summary_thinking: true 把思考改成 low。

新字段更灵活，可以挂在 routes 条目或 search_fallback 上。

  • claudeSearchSummary：forceLow、forceMid、forceHigh 按档注入摘要指令，noForce 不注入。设置后压过 enhance_search 的旧字段。
  • claudeSearchThinking：off、low、mid、high、max 改写这条搜索请求的思考档位。客户端本来没开思考时，回传的思考块会被剥掉，客户端看到的仍是原来的形态。

注入摘要后，徽标从 [Search] 升级为 [SearchSummary-档位]。思考被改写时，API 列额外显示 [原->新]。

search_fallback 自身还保留旧字段：summary_mode: true 对该兜底路由的独立搜索请求注入摘要，档位取 summary_level（默认 low）；summary_thinking: true 把思考改成 low。对应设置了 claudeSearchSummary 或 claudeSearchThinking 时以新字段为准。

优先级：请求由路由自己服务时，用路由自己的值。整条请求转给 search_fallback 时，路由显式设置的字段逐字段压过 fallback，没设置的字段用 fallback 的值。

空搜守卫：noBullshitOnEmptyClaudeSearch

配在 routes 条目或 search_fallback 上，默认关闭。开启后，独立搜索请求如果返回了搜索结果块，但每条结果的内容都是空数组，代理会丢掉上游的整个回答（包括思考过程和编造正文），改发一段「没有搜到，请换关键词重试」的完整流。结果非空或形状不认识时保守放行。

只对 Anthropic 原生口的独立搜索请求生效，不影响 Responses 流量。开启后，健康的上游 200 流也会缓冲到上游结束才转发。触发时日志记 [search-guard]，完成流状态码列显示红色 [空搜]。

思考改写 convertOff2Low

有些上游在关思考时会改用无思考的旧模型，例如 Kimi 文档里的 K2.8 Preview。把「关」悄悄升级成 low，可以让请求留在强模型上。convertOff2Low 就是做这件事的开关。

  • 取值："translate" 只作用于 Responses 翻译口；"all" 同时作用于翻译口和 Anthropic 原生口；不写等于关闭。
  • 做法：下游明确关思考时，代理按 low 发给上游。adaptive 模型发 adaptive 加 effort: low；budget 模型发 budget_tokens: 2048，并受 max_tokens 一半和 1024 地板约束。回传时剥掉思考块，客户端看到的仍是关思考，usage 如实透传。
  • 放弃升级的情况：budget 模型连 1024 都放不下，或者请求强制了与思考互斥的 tool_choice。
  • 上游拒绝思考时，自动回退为关思考并重试一次。
  • 生效路由：翻译口按客户端 model 名预匹配路由；原生口按最终生效的路由，发生图片或搜索兜底交换后取兜底路由的值。

徽标 [off->low] 双色显示在 API 列，前一段是下游口径，后一段是上游口径。历史兜底按所请档位如实显示，不加徽标。

allowNoThinkBlock4Anthropic 决定工具续轮历史缺少签名思考块时的策略：默认 true 先照发，被 400 才自动关思考重试一次；false 则一开始就关。显式关思考的请求不受这个开关影响，仍由 convertOff2Low 管。

全局流式化 convertAlltoStream

开启 convertAlltoStream（默认 false）后，所有非流式 Anthropic Messages 请求都会被代理悄悄改成流式发上游。代理收完整条流后，把内容块原样拼回非流式 JSON，一次性返回给客户端。调用方拿到的仍是它预期的非流式响应。

好处是分类器这类一次性请求也能在控制台看到实时吐字、首字和 tok/s。

  • 只作用于 /v1/messages，已经是流式的请求不受影响。
  • 流中途断开（没见到 message_stop）时，代理还没向客户端写任何内容，可以整体重试。
  • 重试等待期间不发送 SSE 保活，避免污染非流式响应。

状态页与统计

状态页顶部是统计卡片：活跃/等待、发给上游、上游返回、缓存命中、输入（未命中）、输出、重试、分类器、首字、tok/s。在途流和最近完成流各一张表，点行查看内容。

指标定义

  • 总时间：从代理收到下游请求，到把响应全部发回下游。包含内部处理、首字等待、吐字和收尾。
  • 首字：从发出请求到收到首个输出字节的耗时。
  • tok/s：输出 token 数除以流式耗时。
  • token 入/出：该流的总输入 / 输出 tokens，格式 107k/4。输入 = input + cache_read + cache_creation；在途时显示头部/尾部已到达的数值，完成后才准确；未收到的一侧显示 -，例如被下游取消、只拿到头部的流显示 107k/-。在途流该列位于 API 和「字节」之间；最近完成流用它替换「字节」列，鼠标悬停单元格显示该流字节数。
  • 缓存命中：cache_read / (input + cache_read + cache_creation)。缓存写入不算命中，但计入总输入。高命中率主要来自上游模型的原生上下文缓存，代理只透传 usage。中断的流不参与缓存命中聚合，避免把半截上下文算成低命中。
  • 输入（未命中）：只统计未命中缓存的新鲜 input token（中断的流不计入）；总输入 = 未命中 + 缓存读取 + 缓存写入，与各流 token 列「入」同构成。悬停卡片可见该说明。
  • 缓存年龄：按会话和路由锚定，显示最近一次缓存写入距现在多久。同会话同路由有流正在吐字时，最新完成行冻结为方括号形式，表示缓存刚被刷新。开始时刻在 5 分钟内的最新行不会被「保留完成流 N」挤掉。没有会话标识的请求恒显示 -。
  • # 列：#80<-73 表示 80 号流的请求延续自 73 号流。同一个会话、且 73 号的消息链是 80 号的前缀时才会标注。裸 #N 表示没有父流，例如子代理首轮或 /clear 之后。

点击「缓存命中」卡片，弹窗按真实上游模型拆分明细。底部「实测缓存时间」表按 URL 和模型归组，给出缓存存活时间的下界（≥）、上界（<）、各界的形成时间和观测次数。输入不足 1024 token 的流不参与观测。

点击「分类器」卡片看命中与改写明细，按 Claude Code 和 Codex 分列。

「活跃度」打开最近 48 小时的热图，每格 15 分钟，可以切换按请求次数、输入+输出或输出着色。热图保存在配置文件旁的 heatmap.dat，重启不丢。

「清空统计」清空累计统计、最近完成流和活跃度热图，不清在途流和编号，也不清日志。「保留完成流」控制列表行数，默认 10，最大 200。

流查看器

点击在途流或最近完成流的任意一行，下方打开流查看器。内容按钮循环四种状态：请求体 → 输出[渲染] → 输出[流式原始] → 输出[非流式]。

  • 渲染：把 SSE 事件流解析成可读文本。
  • 流式原始：逐字显示 SSE 原文。
  • 非流式：把事件流拼成最终 JSON。流没完整到达时会注明是部分快照。此状态下「交互式JSON」直接对拼好的对象成树。
  • 请求体：复现产生这条流的请求。JSON 自动美化。

链路两侧：「链路」按钮在「代理↔上游」和「下游↔代理」之间切换。默认看代理实际发给上游的请求体和上游回来的原始流。只有两侧有差异的流才双存，例如翻译流和模型改写流。切到没有记录的一侧会自动回退，并在按钮旁提示。

浏览最多显示前 256KB。勾选「储存完整结构体」后，新开始的请求会额外记录完整请求体和输出（不设上限，占内存），查看器出现下载按钮。取消勾选会立即清空已存的完整副本。该开关重启后复位为关闭。

「交互式JSON」始终可用，不需要勾选储存。它把当前内容变成可折叠的 JSON 树，第一层默认展开，更深的层级点击懒展开，并跟随链路侧切换。数据残缺的流不会被冒充成完整版，下载按钮会置灰并说明原因。

「自动跟踪最新」开启时，查看器跟随最新的在途流。「最多显示」控制并排显示的在途流数量。

常见问题

  • Claude Code 没走代理：环境变量必须和 claude 在同一个终端里 export。用 echo $ANTHROPIC_BASE_URL 确认输出 http://127.0.0.1:8080。
  • 改了端口不生效：listen 只在启动时绑定。退出代理再启动。responses_listen 支持热启停。
  • 控制台打不开：多半是主端口被占用或配置有错。直接编辑配置文件修正 listen 后重启。排查启动错误可以临时设置 "log_file": "proxy.log"。
  • 看不到重试：日志页应出现 [attempt N] upstream response status: 429 和 [retry] 行。没有这些行说明状态码不在 retry_status_codes 里，或重试预算已经用完。确定性 4xx（如 400 invalid_request_error：坏 JSON、未签名思考历史）不重试——语义兜底各试一次后直接带原错误体透传（keepalive 流已开时错误详情随 SSE 错误事件下发，状态列记真实状态码而不是 [重试尽]）；408/425/429 与 5xx 即使不在列表里也仍按瞬时错误走体内重试。
  • 启动后没有窗口：正常。程序常驻托盘或菜单栏，从图标菜单打开控制台。
  • Codex 报 503 且代理零日志：系统代理劫持了 127.0.0.1。把 127.0.0.1 加进 NO_PROXY，重启 Codex。Windows 一键脚本会写用户级变量，macOS 脚本会写入 launchd 并持久化。
  • macOS 首次打不开：应用是临时签名。在 Finder 里右键选「打开」，确认一次即可。
  • 保存配置被拒：看页面上的报错。常见原因是 JSON 语法错误、引用了未定义的变量、枚举值写错，或配置里还留着已删除的键。
  • 请求返回 502：没有命中任何路由，且 upstream 为空；或者上游地址连不上。看日志的 [route] 行确认去向。
  • 想保留日志：设置 log_file。默认只留在内存，供控制台最近 500 行使用。
