What this is

Proxy429 is an Anthropic-compatible proxy that runs on your machine. AI clients send requests to it, it forwards them to one or more upstreams, and the whole exchange is visible in a web console.

It does three things.

  • Absorbs 429s and 5xx: exponential-backoff retries, so the client usually never notices upstream hiccups.
  • Routes by model name: routes sends different model names to different upstreams and keys.
  • Translates protocols: turns Codex CLI's OpenAI Responses requests into Anthropic Messages, so Codex can use Anthropic upstreams.
Claude Code ── Anthropic ──▶ 127.0.0.1:8080 ┐
Codex CLI   ── Responses ──▶ 127.0.0.1:8081 ┴─▶ routes / fallback ──▶ upstream

The console lives at http://127.0.0.1:8080/__logs: status, logs and config all live there. Every listener accepts loopback connections only.

Quick start

  1. Start the proxy. On Windows double-click proxy429.exe; on macOS double-click Proxy429.app (if Gatekeeper blocks the first launch, right-click and choose Open); on Linux run ./proxy429. After launch there is only a tray or menu-bar icon, no window.
  2. Open the console. Use the tray menu item "View logs", or open http://127.0.0.1:8080/__logs directly.
  3. Hook up Claude Code. In the same terminal that runs claude: 
    export ANTHROPIC_BASE_URL="http://127.0.0.1:8080"
export ANTHROPIC_AUTH_TOKEN="your API key"
claude
    When the route entry carries api, the token here can be any non-empty string; the proxy injects the real key. Upstreams that only honor a real Authorization: Bearer (e.g. Volcengine ARK) must use ANTHROPIC_AUTH_TOKEN, not ANTHROPIC_API_KEY, or you get a 401.
  4. Hook up Codex CLI. First make sure responses_listen is enabled on the Config tab, then use "Codex one-line setup" at the bottom of the Config tab: copy the command for your OS, run it, and restart Codex. Details in "Codex & Responses translation".

Verify: a request appears under In-flight on the Status tab and a [route] line appears on the Logs tab — the chain works.

Where the config file lives: the first launch generates one with placeholder keys in your user directory.

Console tour

The top bar has three tabs — Status, Logs, Config — plus the Docs button and the language switch on the right. Closing the browser tab only hides the console; the proxy keeps running.

  • Status: stat cards, in-flight streams, recently finished streams. Click any row to inspect that stream's request body and output. Card and badge meanings are in "Status tab & stats" and "Badge dictionary".
  • Logs: live scrolling log. Memory keeps only the latest 500 lines; configure log_file to keep more.
  • Config: edit config.json directly; saving takes effect immediately. See "Editing config".

Editing config

The Config tab can create, rename, delete and switch config files; the list refreshes every 3 seconds. The active config cannot be deleted.

Save & reload validates the JSON, writes the file, and applies it immediately. Reload only re-reads the file from disk without writing. Invalid JSON is never written; the error points at the exact spot.

listen binds at startup only. After changing the main port, exit and restart the proxy. responses_listen is the exception: the listener starts and stops with each save.

Shared variables: vars

When several routes share one key, put the key in the top-level vars and reference it from routes as $NAME or ${NAME}. Rotating a key touches one place.

"vars": { "DEEPSEEK_KEY": "sk-..." },
"routes": [
  { "pattern": "*opus*", "url": "https://api.deepseek.com", "api": "$DEEPSEEK_KEY", "model": "deepseek-v4-pro" }
]
  • Any string value in the file can reference a variable, api and url included. The file keeps the reference verbatim; it is resolved on load.
  • Referencing an undefined variable rejects load or save with a path, e.g. routes[0].api.
  • Variable values must be strings; an empty string counts. Variables may reference other variables, one level deep.
  • A $ not followed by a valid name is left alone, e.g. $5.

Previewing lazyApply

"Preview JSON after lazyApply" shows the config with defaults filled in, read-only, never written. "Copy to editor" puts the result back into the editor; you still save it yourself. Rules are in "Global defaults: lazyApply".

Access control: the forwarding port and the admin endpoints (/__*) always accept loopback connections only. Even if you write listen as 0.0.0.0, LAN devices cannot connect and cannot see the console.

Routing basics

routes wildcard-matches the model name. * matches any run of characters, including none. On a hit, url, api and model override the request.

"routes": [
  { "pattern": "*opus*",  "url": "https://upstream-a", "api": "sk-aaa", "model": "strong-model" },
  { "pattern": "*haiku*", "url": "https://upstream-b", "api": "sk-bbb", "model": "cheap-model" },
  { "pattern": "*",       "url": "https://upstream-a", "api": "sk-aaa", "model": "strong-model" }
]
  • Order decides: entries match in array order and the first hit wins — there is no "more specific wins". If *opus* comes before *opus-4*, claude-opus-4-8 only ever hits the former. Put specific rules first and the * catch-all last.
  • pattern can be an array: "pattern": ["*fable*", "*opus*"] equals copying the route once per pattern. All other fields are shared; position and array order are the match order. An empty array or a non-string member fails the load.
  • Reserved names: the pure * catch-all route is always called Fallback in the Codex menu, and the fast lane is fast_route. No pattern may be exactly one of these names; a colliding route neither takes effect nor enters the menu, and when pattern is an array only the colliding member is disabled. Wildcards like Fall* are unaffected.
  • effort pins the thinking level: when a route sets effort (low/mid/high/max; mid goes upstream as medium), a request whose body at the pin point (after routing, before the search rewrite and the native off->low upgrades) carries adaptive thinking gets its top-level output_config.effort forced to that level, ignoring what the client asked for; a body already at that level is left untouched with no badge. Non-adaptive bodies (budget, thinking off, no thinking field) stay byte-for-byte untouched, explicit thinking-off is never pinned (the convertOff2Low quiet upgrade keeps its own low on both ports), and an unset effort never touches anything. Only the route that actually serves the request counts: classifier, fast, image/search fallback and Responses-passthrough lanes use their own paths. The API column shows the last rewrite as a teal [from->to] badge (a later search rewrite re-badges; the 400 fallback back to thinking-off clears it). The model column also shows the configured level as origModel -> [level] targetModel (appended as origModel [level] when routing didn't rewrite the model), in wire vocabulary (mid shows as medium), even when the body-side rewrite didn't apply; the badge remains the proof of an actual rewrite. The top-level compactEffort (low/mid/high/max) pins context-compaction requests (Claude Code compact, Codex CLI checkpoint compaction) the same way and beats every route effort pin on them; unset it and behavior stays exactly as before. On those requests the model column's [level] slot carries the compactEffort level in place of the overridden route pin (the same origModel -> [level] targetModel position), and an actual rewrite still shows the API column's [from->to] badge.

To see which route won, read the [route] line in the log, or the [Pattern], [Classifier], [Fast], [Multimodal], [Search] prefix on the model column of the Status tab.

Capability fallbacks

After a route matches, if the upstream lacks a capability the request needs, the proxy swaps to a fallback upstream. Search and images are handled in a fixed order.

  • Search requests (carrying the web_search tool): when the matched route is marked no_search, the whole request goes to search_fallback and that upstream searches and answers on its own. Without a search_fallback, the request passes to the original route, which may error.
  • Image requests (without search): when the matched route is marked text_only and the request carries images, it goes to multimodal_fallback. Without one, it passes to the original route, which may reject images.
  • Search wins: a request carrying both search and images is treated as search and goes to search_fallback.

Fallback routes use the same url/api/model shape and support some behavior fields, e.g. thinking and convertOff2Low. Once a fallback kicks in, its own fields apply; search-specific fields follow the per-field rules in "Parameter reference".

To let a search-capable upstream write its own summaries, see "Search enhancement & empty-search guard". To split classifier or fast requests onto their own upstream, see "Dedicated routes".

Dedicated routes

classifier_route

Claude Code's security checks and Codex's approval evaluations send signature requests. A matching request ignores its model and goes straight to classifier_route — a good place for a cheap model, sparing your main quota.

  • classifier_thinking takes off, low, or nothing. Unset leaves the request untouched. off rewrites the request to thinking-off for faster verdicts. low turns thinking off first, then quietly upgrades it to low through the convertOff2Low machinery upstream-side, stripping thinking blocks on the way back — the client notices nothing.
  • classifier_thinking_cc and classifier_thinking_codex override the shared value per source.
  • Classifier requests carry tiny max_tokens (guardian can send as little as 64). When the low policy needs the 1024-token floor, the proxy raises max_tokens by 1024 upstream-side, invisibly to the client.

Overall order: classifier signature requests go to classifier_route first, requests carrying "speed":"fast" go to fast_route next, everything else wildcard-matches routes and finally falls back to upstream.

The Classifier card on the Status tab counts hits; hover for the per-source split and click to enlarge.

fast_route

Requests carrying "speed":"fast" take fast_route. Claude Code's /fast and the fast_route entry in the Codex menu both trigger it. On a hit the proxy adds the fast-lane rate-limit headers to the response, keeping the client in fast mode.

Global defaults: lazyApply

lazyApply is a global default bundle. It only fills fields that a route-like object already supports, exactly as if you wrote the key into every object that does not set it explicitly. It never invents fields and never creates unconfigured optional routes.

  • Per-field precedence: explicit local value (including false and empty strings) > lazyApply > built-in default.
  • Connection trio is inherited: url, api and model come from lazyApply too (written into every object that omits the key, at load time), so the upstream is written once and a route can shrink to {"pattern": "*sonnet*", "effort": "high"}; fast_route may even be {}. A locally written connection key still wins; writing an empty string stops inheritance: "api": "" passes the client's token through, "model": "" keeps the client's model, and "url": "" means no reroute (a routes[] entry still applies its other fields and forwards to the default upstream, classifier_route keeps only its thinking rewrite, and fast_route / multimodal_fallback / search_fallback are not engaged, so the request follows normal routing). pattern and url_response_api are never inherited and stay per object.
  • effort is written per route only: a route's effort pin is never inherited; lazyApply does not offer the field, so a global default can never pin every route's level at once. The top-level compactEffort is the one global effort knob, but it only affects context-compaction requests, never normal traffic.
  • enhance_search replaces whole: a local value replaces the lazyApply object entirely; the two are never merged.
  • Objects can opt out: "noLazyApply": true inside an object stops all inheritance; its own explicit fields still apply.
  • Inherited values join the precedence chain: an inherited claudeSearch* counts as locally written and beats search_fallback's own value. To use the fallback's value, write noLazyApply on that route.

Supported fields are listed under lazyApply in "Parameter reference". The Config tab's preview button shows the expanded result read-only.

Connection & retries

  • listen: the main Anthropic listener address; the template uses 127.0.0.1:8080. Binds at startup only.
  • upstream: the default upstream, used when no route matches. Omit it if you configure a pure * catch-all route.
  • responses_listen: the OpenAI Responses listener address; empty means off. Starts and stops on save.
  • Retry parameters: max_retries is the maximum number of retries, excluding the first attempt. base_delay_s is the first backoff in seconds; later waits double, plus up to 30% random jitter. max_delay_s caps a single wait; 0 clips every wait to 0, i.e. no waiting. total_budget_s is the retry budget for the whole request. retry_status_codes lists the upstream status codes that trigger a retry; an empty array means no status-code retries.
  • respect_retry_after: when the upstream returns a Retry-After header, wait by it first.
  • upstream_header_timeout_s: how long to wait for the upstream's first byte. A timeout is handled as an internal resend; unset means 70 seconds.
  • ping_interval_s: SSE keep-alive interval sent to the client during retry waits; unset means 5 seconds. Non-streaming requests get no keep-alive.

When retries run out, the proxy sends the client an overloaded_error event. The status column shows [retries exhausted]; streams that went through backoff retries show [retried Nx].

Logging: log_request_detail records request-body detail; log_file appends the log to a file; recent_sample_window is the recent-sample window for the TTFT and tok/s stats, unset means 20.

Codex & Responses translation

Set the top-level responses_listen to 127.0.0.1:8081 and the proxy additionally serves /v1/responses at that address. Codex CLI only speaks OpenAI Responses; requests are translated to Anthropic Messages, travel the exact same main pipeline as Claude Code, and the response is translated back to Responses.

Hooking up Codex

The easiest path is "Codex one-line setup" at the bottom of the Config tab. Two commands are generated live from the editor above; they back up and rewrite ~/.codex/config.toml and write the model catalog. Choosing "(Restore default Codex config)" in the dropdown yields a command that fully undoes it. Restart Codex afterwards.

Manual configuration below.

model_provider = "proxy429"
model = "gpt-5-codex"
forced_login_method = "api"

[model_providers.proxy429]
name = "Proxy429 Local Proxy"
base_url = "http://127.0.0.1:8081/v1"
wire_api = "responses"
experimental_bearer_token = "proxy429"

base_url must include /v1 and wire_api must be responses. The token is a placeholder the proxy never checks; the real key is injected by the matched route's api.

Codex reports 503 and the proxy sees nothing: a system proxy is hijacking requests to 127.0.0.1. Put 127.0.0.1 into NO_PROXY and restart Codex. The Windows and macOS one-line scripts write and persist it automatically; the Linux script prints a hint.

Model names and thinking mapping

The model name Codex sends participates in routes matching as usual. The thinking-shape lookup uses the client's original model name and happens before route rewriting. For the mapping table to apply, set Codex's model to the target model name itself.

Models come in two classes. Adaptive models express thinking as thinking:adaptive plus output_config.effort: fable-5, mythos-5, mythos-preview, sonnet-5, opus-4-8, opus-4-7, opus-4-6, sonnet-4-6. All others express it as budget_tokens.

When an alias hits the adaptive table but the actual routed target only supports budget (e.g. the alias is claude-fable-5 while traffic lands on Kimi), write "thinking": "budget" or "adaptive" on that route entry to correct it. The field only affects translated streams.

Thinking, history and the envelope

  • With thinking on, tool-continuation history must carry replayable signed thinking blocks. allowNoThinkBlock4Anthropic defaults to true: send at the requested level first, and only if the upstream returns 400 turn thinking off and retry once, without stripping thinking blocks so the next round's history heals itself. Set it to false to turn thinking off from the start.
  • A forced tool_choice conflicts with thinking. Models that can turn thinking off get thinking disabled for this request while keeping the tool constraint; fable-5 and mythos-5 cannot, so the request errors.
  • Thinking blocks and each search's full results are sealed into an envelope inside the response, restored when the client replays it next round, so the thinking chain and search bodies keep working. Search envelopes are obfuscated per upstream and key; after a key or upstream change they expire automatically, and plaintext URLs or keys never appear in client history.
  • When an old conversation's search blocks have expired upstream, the proxy strips the replayed blocks and retries once, degrading invisibly to a fresh search. The strip count shows as [strip N].

Search enhancement & empty-search guard

Every Claude Code web search runs as its own sub-agent request. A standalone search request is recognized by its final user message starting with Perform a web search for the query. Only the final message counts; the same phrase quoted in history does not. Recognized requests show a teal-green [Search] on the model column.

Let the upstream write summaries: enhance_search and claudeSearchSummary

enhance_search lives on a routes entry and applies when that route is not marked no_search. The proxy injects the summary instruction into the search request itself, still on the route's own upstream, so one request does the search and per-result summaries, and the response passes through unchanged. The legacy summary_level controls detail (low, mid, high, max), and summary_thinking: true turns thinking into low.

The newer fields are more flexible and can sit on a routes entry or on search_fallback.

  • claudeSearchSummary: forceLow, forceMid, forceHigh inject the summary instruction at that level; noForce injects nothing. Once set, it beats the legacy enhance_search fields.
  • claudeSearchThinking: off, low, mid, high, max rewrite thinking for this search request. If the client never asked for thinking, returned thinking blocks are stripped and the client sees its original shape.

After a summary injection the badge upgrades from [Search] to [SearchSummary-level]. When thinking was rewritten, the API column additionally shows [from->to].

search_fallback also keeps its own legacy fields: summary_mode: true injects the summary instruction for standalone search requests on that fallback, at summary_level (low by default); summary_thinking: true turns thinking into low. When claudeSearchSummary or claudeSearchThinking is set, the newer field wins.

Precedence: when a route serves the request itself, its own values apply. When the whole request diverts to search_fallback, fields the route set explicitly beat the fallback per field, and unset fields take the fallback's value.

Empty-search guard: noBullshitOnEmptyClaudeSearch

Configured on a routes entry or on search_fallback; off by default. When on, a standalone search request that returned search-result blocks whose every result body is an empty array makes the proxy discard the upstream's entire answer (thinking and fabricated prose included) and send a fixed "nothing was found, try other keywords" stream instead. Non-empty results, or shapes it does not recognize, pass through conservatively.

It only applies to standalone search requests on the native Anthropic port and never touches Responses traffic. Once on, even a healthy upstream 200 stream is buffered until the upstream finishes before forwarding. Triggers log [search-guard] and mark the status column of the finished row with a red [empty-search].

Thinking rewrite: convertOff2Low

Some upstreams switch to a non-thinking older model when thinking is off, e.g. K2.8 Preview in Kimi's docs. Quietly upgrading "off" to low keeps the request on the strong model. convertOff2Low is that switch.

  • Values: "translate" applies to the Responses translation port only; "all" covers both the translation port and the native Anthropic port; unset means off.
  • How it works: when the client explicitly turns thinking off, the proxy sends low upstream. Adaptive models get adaptive plus effort: low; budget models get budget_tokens: 2048, subject to the half-of-max_tokens cap and the 1024 floor. Thinking blocks are stripped on the way back — the client still sees thinking off, while usage passes through truthfully.
  • The upgrade is abandoned when a budget model cannot fit even 1024, or when the request forces a tool_choice that conflicts with thinking.
  • If the upstream rejects thinking, the proxy falls back to thinking-off and retries once.
  • Which route applies: the translation port pre-matches routes by the client's model name; the native port uses the finally effective route, taking the fallback route's value after an image or search fallback swap.

The [off->low] badge shows two colors in the API column: the first part is the client-side vocabulary, the second the upstream-side one. History fallbacks are shown honestly at the requested level and carry no badge.

allowNoThinkBlock4Anthropic decides the strategy when tool-continuation history lacks signed thinking blocks: true (default) sends first and turns thinking off only after a 400; false turns it off from the start. Requests that explicitly turn thinking off are unaffected and stay governed by convertOff2Low.

Global stream-ification: convertAlltoStream

With convertAlltoStream on (default false), every non-streaming Anthropic Messages request is quietly turned into a streaming request upstream. The proxy reads the whole stream, reassembles the content blocks into the non-streaming JSON, and returns it in one shot. The caller still gets the non-streaming response it expects.

The benefit: one-shot requests like classifiers now show live token output, TTFT and tok/s in the console.

  • Applies to /v1/messages only; requests already streaming are untouched.
  • If the stream breaks mid-way (no message_stop), the proxy has not written anything to the client yet, so it can retry wholesale.
  • No SSE keep-alive is sent during retry waits, avoiding pollution of the non-streaming response.

Status tab & stats

The Status tab opens with stat cards: Active/Waiting, To upstream, From upstream, Cache hit, Input (uncached), Output, Retries, Classifier, TTFT, tok/s. In-flight and recently finished streams each get a table; click a row to inspect it.

Metric definitions

  • Total: from the proxy receiving the downstream request to the full response being sent back. Includes internal handling, first-byte wait, streaming and wrap-up.
  • TTFT: from sending the request to receiving the first output byte.
  • tok/s: output tokens divided by streaming time.
  • token in/out: the stream's total input / output tokens, formatted 107k/4. Input = input + cache_read + cache_creation; in flight it shows what the head/tail has delivered so far and is exact only once the stream finishes, and a side never received shows - (a stream cancelled by the downstream after its head reads 107k/-). On in-flight rows the column sits between API and Bytes; on finished rows it replaces the Bytes column, and hovering a cell shows that stream's byte count.
  • Cache hit: cache_read / (input + cache_read + cache_creation). Cache writes do not count as hits but do count as input. A high hit rate comes mostly from the upstream model's native context cache; the proxy only passes usage through. Interrupted streams are excluded from the cache-hit aggregate so a half-finished context is not counted as a low hit.
  • Input (uncached): only fresh input tokens that missed the cache (interrupted streams excluded); total input = uncached + cache read + cache write, the same composition as each stream's token in/out "in" value. Hover the card to see this note.
  • Cache age: anchored per session and route, showing how long ago the latest cache write happened. While a stream of the same session and route is streaming, the newest finished row freezes into brackets, meaning the cache was just refreshed. A newest row that started within the last 5 minutes is protected from the "Keep finished N" trim. Requests without a session marker always show -.
  • # column: #80<-73 means stream 80 continues from stream 73. It is annotated only when the session matches and stream 73's message chain is a prefix of stream 80's. A bare #N means no parent, e.g. a sub-agent's first round or right after /clear.

Clicking the Cache hit card opens a per-real-upstream-model breakdown. The "Measured cache lifetime" table at the bottom groups by URL and model and gives the lower bound (≥), upper bound (<), how long each bound has stood, and observation counts. Streams with under 1024 input tokens are not sampled.

Clicking the Classifier card shows hits and rewrite details, split by Claude Code and Codex.

Activity opens a heatmap of the last 48 hours, one cell per 15 minutes, colorable by request count, input+output, or output. It is stored in heatmap.dat next to the config file and survives restarts.

Clear stats zeroes the cumulative stats, the finished-streams list and the activity heatmap; in-flight streams, stream numbering and the log are untouched. "Keep finished" controls the list length, default 10, maximum 200.

Stream viewer

Clicking any in-flight or finished row opens the stream viewer below. The content button cycles four states: Request body → Output [rendered] → Output [raw stream] → Output [non-stream].

  • Rendered: the SSE event stream parsed into readable text.
  • Raw stream: the verbatim SSE bytes.
  • Non-stream: the events assembled into the final JSON. An incomplete stream is labeled as a partial snapshot. In this state Interactive JSON builds its tree directly from the assembled object.
  • Request body: the request that produced this stream, pretty-printed JSON.

Both link sides: the Link button toggles between proxy↔upstream and client↔proxy. The default shows what the proxy actually sent upstream and what came back. Both sides are stored only when they differ, e.g. translated streams and model-rewritten streams. Switching to a side with no recording falls back automatically with a note beside the button.

Browsing shows at most the first 256KB. With "Store full payloads" on, newly started requests additionally record the full request body and output (no cap, memory cost), and the viewer shows download buttons. Turning it off immediately purges stored full copies. The switch resets to off after a restart.

Interactive JSON is always available and needs no storage switch. It turns the current content into a collapsible JSON tree: the first level is expanded, deeper levels lazily expand on click, and it follows link-side switches. A stream with incomplete data is never passed off as complete — download buttons grey out with the reason.

With "Auto-track latest" on, the viewer follows the newest in-flight stream. "Show at most" controls how many in-flight streams are shown side by side.

FAQ

  • Claude Code bypasses the proxy: the environment variables must be exported in the same terminal that runs claude. Check with echo $ANTHROPIC_BASE_URL — it must print http://127.0.0.1:8080.
  • A port change does not take effect: listen binds at startup only — exit the proxy and start it again. responses_listen hot-starts and hot-stops.
  • The console will not open: usually the main port is taken or the config is broken. Fix listen by editing the config file directly and restart. To chase startup errors, temporarily set "log_file": "proxy.log".
  • No retries visible: the Logs tab should show [attempt N] upstream response status: 429 and [retry] lines. If they are missing, the status code is not in retry_status_codes, or the retry budget is already spent. A deterministic 4xx (e.g. a 400 invalid_request_error: malformed JSON, unsigned thinking history) is not retried — after the semantic fallbacks get their one shot, the upstream error passes through with its body intact (when a keepalive stream is already open, the detail rides inside the SSE error event and the status column records the real code, not [retries exhausted]); 408/425/429 and every 5xx keep the in-body retry even when not listed.
  • No window after launch: normal. The program lives in the tray or menu bar; open the console from the icon's menu.
  • Codex reports 503 with zero proxy log: a system proxy hijacked 127.0.0.1. Add 127.0.0.1 to NO_PROXY and restart Codex. The Windows one-line script writes a user-level variable; the macOS script persists it into launchd.
  • macOS will not open the app the first time: the app is ad-hoc signed. Right-click it in Finder and choose Open once.
  • A config save is rejected: read the on-page error. Common causes are JSON syntax errors, undefined variable references, wrong enum values, or removed keys left in the config.
  • A request returns 502: no route matched and upstream is empty, or the upstream address is unreachable. Check the [route] line in the log to see where it went.
  • Keep logs: set log_file. By default logs stay in memory only, feeding the console's latest 500 lines.
